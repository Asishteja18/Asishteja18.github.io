Normalise a feature

Every model you ever train will choke on unscaled data. The fix is four lines of plain Python — and understanding it now means StandardScaler is never a black box later.

The problem

Say you are predicting house prices from two features: number of bedrooms (1–5) and floor area in square feet (500–4000). To a model that measures distance, area completely drowns out bedrooms — not because it matters more, but because its numbers are bigger.

# distance is dominated by the larger-scale feature
house_a = [3, 1500]
house_b = [5, 1520]
# bedrooms differ by 2, area by 20 → the model only "sees" area

The fix

Rescale each feature so it has mean 0 and standard deviation 1. Then every feature speaks in the same units: "how many standard deviations from average am I?"

def standardise(xs):
    mean = sum(xs) / len(xs)
    var  = sum((x - mean) ** 2 for x in xs) / len(xs)
    sd   = var ** 0.5
    return [(x - mean) / sd for x in xs]

That is the whole idea behind sklearn.preprocessing.StandardScaler. The library version adds edge-case handling and the ability to apply the same mean and sd to your test set — which matters enormously, and is the subject of lesson 06.

Watch out If every value is identical, sd is 0 and you divide by zero. Real scalers return zeros in that case. Your exercise has to handle it.

Why this is lesson 04

Writing it by hand costs you five minutes. Not writing it by hand costs you a week later, the first time a model performs badly and you cannot tell whether the problem is the data, the scaling, or the model.
